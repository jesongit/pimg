# 存储指南

归档保存完整原件或无损视频片段，永久发布提供固定外链，临时存储保存有保留期的查看副本。

## 用途与选择

| 用途 | 数量 | 可用方式 |
| --- | --- | --- |
| 归档 | 至少一个，可多选 | 本地、Telegram、R2 |
| 永久发布 | 一个首选 | 本地、配置公开域名的 R2 |
| 临时存储 | 一个首选 | 本地、R2 |

首份归档校验通过后文件可用，其余选定归档后台补齐。新增选择会补齐已有文件，取消选择保留已有副本。发布或临时首选失败时，可降级到其他启用且支持该用途的实例，已有副本按实际记录读取和清理。

在「存储 → 用途与同步」分别设置本地与网络同步速度，单位均为 MiB/s。本地同步限速默认 64，仅控制后台本地复制，不限制本地校验，也不受加速时段影响；普通/加速限速控制 TG、R2 等网络同步，默认分别为 1、8，加速时段为北京时间 02:00–06:00。涉及网络的来源读取或目标写入仍受网络限速约束。本地与网络限速可设为 1–1024；保存后立即生效，无需重启，当前后台任务可能让位重试，已校验副本保留。

TG 上传采用最多 4 路、每块 512 KiB 的流式传输，下载按 1 MiB 顺序读取，减少网络往返等待；文件任务仍只有一个闲时通道，沿用前台优先、工作空间限制和完整性校验。限速是上限，实际吞吐仍取决于网络、提供方和磁盘。缓存缩略图与短时原图读取不再立即中断闲时归档；持续读取或预览重建仍会让归档让位，写入、删除和移动等操作继续立即让位。重试沿用相同内容、布局和存储策略下已完成校验的远端分片；本地分片先检查大小和修改时间，变化或缺少记录时重新完整校验。新分片首次写入及手动校验仍完整回读。

每个实例分别设置优先级、是否允许加密、是否分片及分片目标大小。默认分片目标为 256 MB，本地默认不加密、不分片。优先级数字越大越优先，同级结合可用性和传输表现选择；多副本用于独立保存及换源，不是带宽拼接。

## 本地目录

在「存储」新增本地实例，填写容器内可读写的文件夹。系统管理其中的 `archives/` 和 `display/`，实例根目录不能重叠或覆盖上传工作区、密钥与会话目录。

自定义目录需要持久挂载，例如 `/srv/pimg-library:/library`，在后台填写 `/library`。已有文件引用的位置不能直接换到空目录，应新建实例并按用途迁移；旧文件继续按原记录读写。

## Telegram

1. 在 [my.telegram.org](https://my.telegram.org/apps) 创建应用，取得 API ID 和 API Hash。
2. 管理员在「存储 → 连接管理」填写凭据，通过手机号、验证码和可选两步验证密码登录。
3. 选择 Telegram 归档用途。服务端使用统一管理员会话，为 PIMG 用户分配私有论坛超级群，相册对应群内话题。

普通用户无需配置 Telegram 应用、账号或群。会话由主密钥加密保存在数据目录，备份时与原密钥一起保留。会话失效、撤销或丢失时需重新授权，不要让多个实例同时占用。

相册可关联既有独立话题，首次关联选择扫描起点；后续由消息更新及增量补漏处理，仍可手动补新和重试。归档使用文档或加密载体，不以压缩后的 Telegram 图片冒充原件。

## Cloudflare R2

新增 R2 实例时填写端点、桶、对象前缀和访问凭据；永久发布还需公开域名。临时副本可使用独立公开域名或受支持的签名方式。

归档、永久、临时对象有独立前缀及清理边界。建议永久与临时使用不同桶；共享桶时使用互不覆盖的前缀，核对生命周期规则只作用于临时对象。撤销发布需要清 CDN 时，配置对应 Cloudflare 凭据和 Zone ID。

凭据在网页保存后以数据库中的加密配置为准，不应写入公开仓库。

## 加密、原件与分片

上传或导入选择加密，且目标存储允许加密，才加密该份副本。同一文件的不同存储可以有不同实际加密状态，详情逐项显示。服务端持有解密能力，不是端到端加密。

完整原件保留字节和格式，兼容查看只生成派生文件。视频归档分片复制可保留的压缩流，不为归档而重新编码；无法在容量内无损切分时明确失败并保留来源。

只有片段时按片段查看和下载，不能当成字节一致的完整源文件。需要保留源容器时，至少保留一份完整原件归档。

## 临时副本

主动查看原件会准备正式本地副本，正式本地副本不随兼容缓存过期而删除。临时存储副本受保留期限制，链接另受有效期限制，不超过副本剩余期限。

缓存、CDN 与浏览器可能保留已加载内容；撤销授权控制后续请求，不能撤回客户端已经保存的内容。
