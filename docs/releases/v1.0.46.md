# v1.0.46

修复归档同步任务的无限重排队循环（页面变慢与转码被饿死的真正根源），并给核显编码加挂起保护。

- 修复：停用的归档存储实例仍被列为「必须有就绪副本」的目标——同步执行会跳过停用实例并报告成功，而 30 秒一次的校对仍认为副本缺失，于是一遍遍重新入队。线上一天产生 151,506 个归档任务（仅 3,659 个文件、其中 800 个文件各被重复同步约 189 次），两个任务 worker 与 CPU 长期被打满，页面查询和视频转码都被拖慢。现在校对、入队与上传策略计划只统计**启用中**的归档实例；重新启用实例会自动恢复同步。
- 核显编码挂起保护：GPU 驱动挂起时进程会阻塞在内核 DRM 上而非报错。现在转码输出 60 秒无增长即中止本次尝试并回退软件编码，且硬件失败后在本进程内直接禁用硬编，不再让每个视频都白等一分钟。
- 已完成的归档流水仍按「日志保留天数」清理（默认 30 天）；如需更快缩小日志页历史，可在设置中调小。

Docker 镜像：`posase/pimg:v1.0.46`，仅支持 `linux/amd64`。沿用 schema 30，不新增数据库迁移。升级步骤见[部署与升级](../deployment.md#升级已有实例)。
