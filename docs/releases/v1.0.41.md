# v1.0.41

视频直接播放能力全面扩展，兼容版本改为边转换边播放，转码不再降分辨率。

- 浏览器按 `canPlayType` 探测解码能力并上报：H.264、8 位 HEVC（Main）、10 位 HEVC（Main10）、AV1、VP9 画面，以及 AAC、MP3、Opus、AC-3/E-AC-3、FLAC 音轨。装了 HEVC 解码扩展的 Edge/Chrome 现在可直接播放 10 位 HEVC，不再整段转码。
- MP4/M4V 内所有画面与音轨受支持时原样播放；其他容器（MKV/MOV/TS/AVI 等）只做重封装（stream copy），保留原始 10 位画面与 AC-3/Opus 等音轨。重封装缓存按能力指纹区分，不会把含 HEVC/AC-3 的版本发给不支持的浏览器。
- 只有音轨不兼容时保留原画面、仅转音轨的判定改为按浏览器能力计算，不再固定要求 H.264。
- 兼容版本（重封装与转码）改为流式输出 fragmented MP4：播放从首个分片就绪即开始，不再等待整段转换；转换完成的版本自动缓存，后续打开按 Range 完整拖动。转码保留源分辨率，去掉固定 720p 上限；HDR 仍转码并做色调映射。
- 保留旧行为的兜底：能力探测缺失的旧客户端按严格 H.264/AAC 基线决策；`compatible=auto` 的失败回退仍按严格基线选择，不回环到刚失败的编解码。
- 代理流量额度耗尽时停止 Telegram 重连风暴：额度耗尽后 1 秒内停掉 SDK 的内部重连拨号，等待额度恢复后自动重连，不再全天候空拨；连接失败告警按类型去重（同类型 10 分钟最多一条），运行日志不再被刷满，诊断接口仍保留每次失败记录。

Docker 镜像：`posase/pimg:v1.0.41`，仅支持 `linux/amd64`。沿用 schema 30，不新增数据库迁移或会话格式变更。升级步骤见[部署与升级](../deployment.md#升级已有实例)。

边转边播的首次播放为顺序流，拖动到尚未生成的位置需等待转换推进；完成后重新打开即获得完整拖动能力。`file-browser/content` 的 `stream=1` 由 `/view` 自动附带，无需手工构造。
