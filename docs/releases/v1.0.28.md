# v1.0.28

优化归档传输效率，并将本地复制与网络同步限速分开。

- Telegram 上传采用最多 4 路、每块 512 KiB 的流式传输，下载按 1 MiB 顺序块读取，减少小块串行请求的网络往返等待。保留精确长度、哈希校验、稳定操作编号和取消恢复。
- 「存储 → 用途与同步」新增「本地同步限速」，默认 64 MiB/s，支持 1–1024 MiB/s；只控制后台本地复制，不限制本地回读校验或哈希，也不受网络加速时段影响。
- 普通/加速同步限速继续控制 TG、R2 等网络传输。旧配置的网络限速和时段保留，缺少本地限速时使用默认值。保存后即时生效，无需重启，当前闲时任务可能中断重试，已校验副本保留。
- 涉及远端来源的复制继续遵守网络限速，目标为本地时也不会绕过。文件同步仍使用一个闲时通道，保留前台优先、工作空间限制和完整性校验。
- 性能诊断新增 `archive_verify` 阶段，便于区分上传与回读校验耗时。

限速是上限，实际速度取决于网络、代理、Telegram/R2 和磁盘；模拟延迟测试不代表线上提速倍数。

Docker 镜像：`posase/pimg:v1.0.28`，仅支持 `linux/amd64`。沿用 schema 30，从 v1.0.27 升级不新增迁移；保留原数据卷、运行卷、配置、密钥、会话与来源挂载，仅替换镜像。升级步骤见[部署与升级](../deployment.md#升级已有实例)。
