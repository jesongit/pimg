# v1.0.35

新增共享代理的日/月流量额度，达到上限后保留任务进度，额度恢复后自动继续。

- 在「存储 → 连接管理 → 代理流量限制」设置额度，默认每日 10 GB、每月 300 GB（1 GB = 10 亿字节）。R2 与 Telegram 共用统计，仅累计实际经过代理的上传、下载及连接协议字节；直连和本地复制不计入。
- 可分别校准当前日/月已用流量，保存后继续累加；只修改其中一项不会覆盖另一项的实时用量。跨周期的旧校准表单会被拒绝，避免覆盖新周期数据。
- 日额度可配置每天刷新的时、分，默认北京时间 00:00；月额度可配置每月几号刷新，默认 1 日北京时间 00:00。选择 29–31 日时，缺少该日期的月份按月底刷新。修改刷新规则保留当前已用量。
- 达到任一上限时，相关任务进入等待，不消耗失败重试次数；周期刷新、提高额度或调低已用量后自动继续。已保存的进度、用量与配置在重启后保留，取消的任务不会被重新唤醒。切换代理连接后会重新判断任务能否继续。
- 超限等待不再被当作归档失败或提供方故障；Telegram 连接在额度恢复后可自动重连。并发在途流量可能产生少量额外字节，仍计入已用量，提供方账单可通过手动校准对齐。

Docker 镜像：`posase/pimg:v1.0.35`，仅支持 `linux/amd64`。沿用 schema 30，无新增数据库迁移；升级保留账号、密钥、Telegram 会话、原件及存储配置。已有代理在首次升级后从零开始统计，可手动校准现有用量。升级步骤见[部署与升级](../deployment.md#升级已有实例)。
