# v1.0.39

优化任务与日志页首次打开时的数据库查询，减少历史积压较大、任务结果较长或后台持续写入时的等待。

- 任务分组与计数不再在多个中间表中复制全部历史任务结果；仅在单任务分组需要展示结果时按主键读取，保留原有结果与进度语义。
- 任务页只汇总候选操作和导入批次的进度；默认日志页只计算历史候选的进度，保留接收关联、状态筛选、分页、重试及日志隐藏规则。
- 日志补充信息改走只读连接池，存储名称按文件 ID 集合查询；任务页读取不再执行无变化的过期清理写事务，减少与后台工作争用写连接。
- 增加后台写事务占用、较大单任务结果及查询一致性回归，并提供隔离性能测量入口。

在同机 12002 条合成任务、每条历史结果约 2KB 的隔离数据库上，三次直接查询的中位数：任务列表约 918 → 189ms，日志列表约 2225 → 531ms，任务计数约 619 → 184ms，耗时下降约 70%–79%。未使用 HTTP 缓存，未清空操作系统文件缓存；数据规模、硬件与实际并发会影响部署后的耗时。

Docker 镜像：`posase/pimg:v1.0.39`，仅支持 `linux/amd64`。沿用 schema 30，无新增数据库迁移；升级保留账号、密钥、Telegram 会话、原件、存储与代理额度配置。升级步骤见[部署与升级](../deployment.md#升级已有实例)。

本次发布不自动更新已有部署，线上升级后的首次页面体验及真实 TG／R2 提供方仍需在实际环境验收。
