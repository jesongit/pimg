# v1.0.54

修复登录限流和图片解码的安全边界，并减少首页加载与后台列表查询开销。

## 安全修复

- 登录密码失败同时按来源 IP 和目标账号计数。其他账号成功登录不再清空来源的失败预算，防止借助已知账号反复重置限流；保留两步验证的独立限制与并发校验。
- 图片超过 4000 万像素时立即拒绝生成预览，不再切换到其他解码器继续处理。FFmpeg 图片路径增加源尺寸预检和解码器像素限制；HEIF 先用 `heif-info` 检查原图画布，兼容转换也使用相同策略。
- 图片元数据与媒体处理诊断输出增加大小限制，避免异常输出持续占用内存。
- Go 工具链升级至 1.26.10，修复已失信中间证书的校验问题（GO-2026-6809）。React Router DOM 升至 7.18.5，Vite 升至 6.4.5，并同步正式依赖锁文件。

## 性能与加载

- 文件列表批量读取公开展示、发布加密状态和临时副本加密状态，减少逐文件查询，保留用户隔离和授权检查。
- Token 最近使用时间按一分钟粒度合并写入，减少无关缓存失效；撤销及账号停用仍立即参与每次请求的鉴权。
- 登录、管理入口和各后台页面按路由延后加载。脚本分块加载失败时提供重新加载入口。
- 本地构建的首页主 JS 从约 703 KB 降至 302 KB，gzip 估算从约 219 KB 降至 98 KB；实际访问体验取决于网络与浏览器缓存。

## 升级说明

- Docker 镜像：`posase/pimg:v1.0.54`，平台 `linux/amd64`。
- 数据库仍为 schema 31，从 v1.0.53 升级无新增迁移。继续使用原数据、密钥、TG 会话、存储及运行目录，不重新初始化。
- 登录仍采用 5 次失败、15 分钟窗口；共享 NAT 或反向代理来源会共享 IP 预算。完整成功登录不会再清除该来源其他失败记录。
- 超过像素上限的图片原件不会被删除，但其新预览和图片兼容转换将被拒绝。尺寸限制不能替代容器对原生媒体进程的资源配额。
- 非 Docker 部署需要 Go 1.26.10 或更新修复版本；HEIF 预览需要 libheif 的 `heif-info` 与 `heif-thumbnailer`，正式镜像已包含。
- 升级后若旧标签页提示页面加载失败，重新加载即可获取本版本脚本。

升级步骤见[部署与升级](../deployment.md#升级已有实例)。
